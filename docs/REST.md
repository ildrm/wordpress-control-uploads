# REST API

Namespace `content-firewall/v1`. WordPress cookie authentication requires its normal REST nonce; application-password requests use WordPress authentication. Nonces do not grant capabilities. Every endpoint has a permission callback. Blog context scopes all object reads.

| Endpoint | Method | Capability / behavior |
|---|---|---|
| /uploads | POST | upload_files; one genuine multipart file, WordPress and plugin limits, private queued receipt |
| /uploads/{id} | GET | read; owner or reviewer only, summarized progress/accepted attachment ID |
| /simulation/file | POST | manage policies; multipart file and optional Policy JSON, private analysis, never publish |
| /scans | GET | review queue; keyset `after`, bounded `limit`, optional state/reviewer/team/overdue |
| /scans/{id} | GET | review queue; normalized evidence, original provenance summary, case assignment/appeals/notes, no private path/key |
| /scans/{id}/preview | GET | reveal_sensitive_content; explicit safe raster derivative |

| /bulk | POST | review queue; ≤50 revision-bearing items, per-item results |
| /my-uploads | GET | authenticated read; own summarized records |
| /scans/{id}/appeal | POST | authenticated owner only; reason |
| /reviewers | GET | eligible current-site reviewer directory; cursor |
| /queue-views | GET | review queue; current user/site saved views |
| /queue-views/save | POST | review queue; at most ten unique typed views |
| /onboarding | GET | manage firewall; saved step/settings/policy/health |
| /onboarding/save | POST | manage firewall; sequential step, permitted settings, optional authorized preset |

Conflict/stale revisions return 409; unauthorized operations 403; absent records 404; validation/configuration errors expose stable codes with a generic message. Raw exception text, sensitive extracted text and provider authentication details are not responses.

For pending uploads, normal WordPress media endpoints return the upload gateway's private reference error rather than a public attachment. The dedicated headless `/uploads` route instead returns a private case/status summary; the worker publishes accepted reconstructed derivatives. `/uploads/{id}` omits findings, reasons, original identifiers and paths and reveals the attachment ID only after accepted publication. Real-file simulation uses `/simulation/file` and never creates a scan or publication job. Machine-readable routes are generated by `tools/openapi.py` from controller route declarations.

Responses use `Cache-Control: private, no-store, max-age=0` and vary on authentication headers/cookies. Previews verify the snapshot hash and expiry before reconstruction. Bulk JSON is fully shape-validated before any item mutation; valid batches then return per-item outcomes. Settings reject null, unknown keys and wrong scalar types, with shared runtime defaults. Enforced network policies cannot be changed through local repository or CLI imports; `/network-policy` creates a new reserved, immutable network version.

`docs/openapi.json` includes 36 request/domain/response schemas across 30 routes. `python3 tools/openapi.py --check` detects generated-document drift. Implemented response DTOs, database numeric strings, UTC dates, processing/retention bounds and not-found responses are documented. Multipart requests and owner-safe progress/real-file reports are documented; broader product acceptance remains open. Onboarding accepts only its permitted settings subset and cannot skip saved steps; semantic constraints supplement the generated schemas.

Assignment actions accept `owner_id` plus optional `assignment:{team,priority,sla_at}`; other actions cannot set assignment. Reviewer eligibility is checked server-side. Terminal auxiliary edits advance revisions, while annotation of queued work preserves the worker revision. Team strings are bounded, priority is 0–1000 and a new UTC deadline must lie between now and 366 days. Saved views include state/owner/team/overdue filters; their IDs are unique within the ten-view list. Settings deep-merge nested retention/processing updates and reject unsupported values.

Headless files are checked against WordPress MIME/maximum-upload/network quota and plugin limits, require upload_files capability, share upload quotas/suspension, and always pass through the private queue. Both multipart routes reject forged local-path parameters and multiple file parts. File simulation accepts an optional unsaved schema-1 policy, shares the scanner's analysis/transform decisions, and reports findings, triggering rules, risk, normalized provider timing/cost and measured summaries without raw words/codes. Configured provider calls can consume budget. Sample/work files are cleaned after the request; provider usage/cache/minimal audit remain. No scan row or publication job is created by simulation. Erased operational stubs are not returned by moderator detail reads.

File simulation uses server-controlled `simulation` context/current user roles and normal trust; synthetic and retained-history simulation supply other context comparisons. Exact blocklists and hard security are evaluated before remote work. A monitor decision is labeled separately from enforcement. Tenant mismatch is rejected at receipt before private file or policy writes.
