# Privacy and data handling

The plugin has no product telemetry. Operators explicitly configure providers using deployment variables/constants and must disclose them. Reduced images/PDF page images and reduced audio clips can still contain personal content. Raw provider responses, OCR/transcript words, QR payloads and credential values are excluded from persisted scan evidence, audit metadata, notifications and diagnostics. WordPress reviewer notes, appeal reasons and original filenames can contain personal information.

Private originals use separate persistent storage outside served roots. Public accepted files are reconstructed independently. Raster reconstruction strips metadata and may flatten animation; PDF reconstruction flattens text/forms/links/signatures; video/audio re-encoding changes media and removes imported metadata/chapters. Original Content Credentials are reported privately and are not preserved in reconstructed public copies. See [media processing](MEDIA-PROCESSING.md) before enabling those features.

Settings and Setup validate independent retention classes:

| Class | Default | Expiry behavior |
|---|---:|---|
| Private originals | 7 days | Expiry is set at receipt. Previews, scans and reapproval reject expired files before cleanup. Held local public derivatives are withdrawn. Changing the setting affects new originals, not existing deadlines. |
| Accepted scan metadata | 90 days | From receipt; remove identifying scan/evidence/case data and the private original. A minimal accepted attachment/state stub preserves publication eligibility. |
| Held/rejected scan metadata | 30 days | From receipt; withdraw supported current local media, cancel scan jobs, erase identifying fields/evidence/cases/notes/appeals and mark deleted. |
| Audit | 180 days | Delete aged signed audit rows. Independent signatures prove neither retention completeness nor absence of deletion. |
| Analytics and feedback | 365 days | Delete aged daily usage and evaluation rows. |
| Completed/failed jobs | 7 days | Delete aged done/dead jobs; active work is not age-deleted by this class. |

Each class accepts 1–3650 days. Cleanup is bounded, scheduled and retryable; metadata batches of 100 schedule continuation. Audit/usage/job cleanup runs in bounded batches on retention ticks. Audit expiry can also apply to erasure-retained audit records. Temporary files/workspaces expire after 24 hours of inactivity following a crash. Backups, provider retention, CDN/offload caches, core WordPress attachment metadata/public files and downloaded copies require operator policies; the plugin cannot erase them all.

WordPress privacy export pages through owned scans/findings/cases/notes/appeals/audit, policy authorship, reviewer feedback, site-scoped saved views and an active administrator-managed upload suspension. Identifying authorship records created by the requester are included as applicable. Private paths/storage keys and raw media are not exported. Owned scan exports include the SHA-256 fingerprint and bounded context/signals, including original-credential summaries when present. Exported records can contain other reviewers' rationale on the requester's own case; operator privacy review remains necessary.

Erasure uses tenant and publication locks, resolves outstanding local media intents first, removes owned private originals and related evidence/review records, cancels relevant queued work, removes saved-view preferences, and anonymizes the requester's authorship/assignment/feedback. It processes the first remaining batch rather than skipping records with a changing offset. It preserves accepted public media and its minimal gate stub; WordPress's separate eraser and the operator handle core media. Publication after an erasure cannot recover deleted private originals.

`privacy_retain_audit` defaults true. Erasure explicitly reports retained signed security audit records and the configured retention limit. False removes related audit rows instead of silently rewriting their signatures. This setting is operator policy, not a legal determination. Retained audit may still identify actors/owned objects, and backup/third-party erasure needs separate handling.

Credentials stay outside the database/JavaScript. Production audit signing requires a dedicated random `CF_AUDIT_KEY` (32–4096 bytes) outside the database. Development/staging may use WordPress salts only when no key is explicitly configured; salt rotation changes verifiability and WordPress fallback material can be DB-stored. Explicit empty/weak keys are rejected. Only summaries/labels from offline C2PA verification are retained, not raw manifests. Extracted text and matched DLP values exist in memory only. SANITIZE handles supported bounded text/custom patterns and located raster findings; unsupported, unlocated or uncertain transformations remain in review.

Suggested disclosure: “We inspect uploads to enforce our file security and content policies. Depending on configuration, reduced media may be processed by the providers named here. Files awaiting review are private and retained for the stated period. Reconstructed public media may lose metadata, signatures or interactive features. Contact us to appeal a decision or request your records.” Adapt this to actual providers, transformations, residency, retention and operator obligations; it is not a completed legal/privacy acceptance review.

Implementation evidence: `tests/Integration/privacy.php` exercises export, more-than-one-page erasure, audit policy/signature handling, active-job cancellation, accepted-media stubs and retention. [WordPress exporter guidance](https://developer.wordpress.org/plugins/privacy/adding-the-personal-data-exporter-to-your-plugin/) and [eraser guidance](https://developer.wordpress.org/plugins/privacy/adding-the-personal-data-eraser-to-your-plugin/) describe the hooks used.

Real-file simulation privately copies the sample for immutable analysis, shares the normal evidence/transform rules and deletes its sample/work on success or failure. It creates no scan record, attachment or publication job. Provider usage/cache and a minimal audit event can be retained; actual configured provider requests may incur cost. Simulator responses omit raw extracted words, code payloads and paths. Headless upload/status has owner/reviewer authorization and returns progress summaries only; accepted derivatives are published by the normal worker.

An active `cf_upload_suspended` control is exported and explicitly reported as retained during erasure. Removing upload records does not silently unban an account. This global WordPress user control is managed by the administrator/integration; it has no automatic plugin expiry. The operator must define/review its purpose and duration and handle it separately from audit retention. Deactivation/data erasure does not remove this external account restriction.
