# Operator runbook

Set `CF_PRIVATE_DIR` to a persistent absolute directory outside WordPress, the web-server document root and public uploads. Its owner must match PHP/worker users; mode 0700 with contained files mode 0600. The temporary default is useful for development but is not a production retention guarantee. Back up the private directory together with operational tables; never publish it via a media-offload plugin.

Configure ClamD with current signatures and resource limits; set `CF_CLAMD_SOCKET` to a local Unix socket and require malware scanning in Settings. Do not expose unauthenticated ClamD TCP. Configure needed provider credentials and disclosure; no external provider is required for security-only operation.

Run `wp content-firewall worker run --limit=20 --seconds=25` every minute using system cron. WP-Cron is a trigger, not a realtime guarantee. Watch ready/dead/leased counts, last worker run, provider failure counts and oldest pending work. During outages use private hold; avoid automatic fail-open for mandatory controls.

Restore interrupted jobs through their leases. Preserve correlation/scan IDs for support. Do not include raw uploads or OCR in incident logs. Retry transport/429/5xx failures with backoff; permanent schema/auth errors need configuration or adapter fixes.

Roll out with Security Only, then monitor-mode content policies and lawful evaluation. Validate category/provider coverage before adding automatic enforcement. Audit override reasons. Expired licenses must never relax security; licensing is currently not implemented.

Deactivate preserves records and stops schedules. Uninstall requires explicit delete-on-uninstall for database removal. Private originals need reviewed storage cleanup before removing tables; review the uninstall acceptance notes before deployment.

Troubleshooting: permission/root errors → verify private directory; provider unavailable → verify deployment credentials and account region; pending backlog → run CLI worker and inspect dead letters; PDF → configure and test the bounded local path in MEDIA-PROCESSING.md; Office/archive → reconstruction is unavailable, so keep held.

Review fixes: a rescan request pins the current policy and commits its queue job with the new revision. Workers can resume publication after a committed result. Terminal scanning failures are shown as FAILED; inspect the stable error and request a new rescan after correcting the cause. Retryable publication failures retain the decision so the next attempt does not repeat provider calls.

Reject/quarantine/delete and held library decisions remove local attachment originals, sizes, source companions and image-edit backups. Reapproval reconstructs from the retained private original and preserves the attachment ID, with a new derivative URL. Cached/CDN copies, offload storage, external links and previously downloaded files require deployment-specific removal. Unsupported or shared local file locations return an error. Review privacy expiry before withdrawing an original that may be needed for reapproval.

Only Privacy Safe metadata reconstruction is supported. Rule effects that have no executor are rejected when saving a policy. Do not advertise privilege suspension, content unpublication or notifications as functioning rule effects. Missing content-category evidence and incomplete required consensus go to human review.

Workers reconcile tenant-private `operations` intents before normal jobs. Metadata failures remain pending until recovery completes. A publication retry reconciles its own previous intent, so it cannot overwrite an orphan's cleanup record. Inspect `recovery_operations`, `issues`, dead jobs and recovery errors in diagnostics. A replacement file at a planned withdrawal path is never blindly removed; `SECURITY.MEDIA_CHANGED` requires operator investigation. Do not edit/delete journals to suppress an error. Back up the private directory, including operations, with the database.

Working derivatives use a tenant-private work directory; inactive work older than 24 hours is cleaned in bounded worker batches. Original-file expiry also blocks previews/rescans/republication before the deletion job executes. Full 100-item retention batches schedule continuation. Separate original/accepted metadata/held metadata/audit/analytics/job limits are configurable in Settings; see PRIVACY.md for defaults and erasure policy. Opt-in uninstall recovers media intents and removes recognized tenant work/private files before dropping records; unexpected paths halt removal.

SANITIZE redacts supported bounded plain text/custom patterns and located requested raster regions. Missing image locations, unsupported transforms or unsafe pattern evaluation require review. OCR conditions alone do not supply a text redaction transform. Provider probabilities and a labeled SANITIZE state are not proof that a prohibited region was removed.

Run Setup to save progress, choose a starting policy and configure limits. Finishing Setup does not establish provider quality or deployment acceptance. Assign reviewer/team/priority/UTC deadlines from the queue; workers escalate unresolved breached deadlines. Saved views are user/site-scoped. Review approval/rejection/quarantine/private-original deletion require an explicit UI confirmation and rationale; API authorization and revision checks remain mandatory.

Local PDF/video/audio/provenance features default off. Configure the absolute paths in MEDIA-PROCESSING.md and run the benign native suites on the worker host before enabling each flag. CLI and web workers must receive consistent variables/tool permissions. Health reports enabled/configured/executable booleans without revealing paths; executable permission does not prove a binary's dynamic libraries work. Maintain tools, deny native-parser network access, bound OS resources and preserve private temporary storage. Offline C2PA requires the pinned version and optional reviewed trust anchors.

Schema 2 adds metadata erasure. Activation, admin and CLI requests attempt migrations; frontend/cron alone is not a migration mechanism. After an upgrade explicitly run `wp content-firewall database migrate`, then verify schema and errors in health before restoring workers. Back up DB/private storage together. Erasure/retention can remove reapproval material and review evidence; select limits and audit policy before deployment. Core public media, backups and offload/CDN copies need their own retention/erasure/revocation controls.

When the optional publication gate is enabled, covered block/legacy image references, explicit gallery/playlist IDs and featured media are checked during ordinary WordPress saves as well as REST saves. Unsafe ordinary saves preserve content as draft and show an editor notice. Scheduled posts are rechecked before the core publish callback; unsafe schedules are cleared and saved as draft. Featured-media changes to a published/scheduled post hold it before storing an unapproved reference. Raw URLs without supported attachment IDs, custom shortcode/meta references, direct `wp_publish_post`/SQL status writes and third-party bypasses still need explicit integration; this is not universal content-reference coverage.

Headless integrations should POST one multipart `file` to `/uploads` and poll `/uploads/{id}` using WordPress authentication. The worker must run for Security Only uploads too. Responses disclose only progress and an accepted attachment ID. Never serve a private original using this case ID. Policy file simulation is explicit, ephemeral analysis rather than a library import; it never publishes or queues publication and may charge configured providers. Consensus now requires two distinct adapters for each requested content category and each inspected page/frame; local text/repeated frames or a transcript-only adapter cannot satisfy image-category agreement.

Ownership is renewed/checked inside scan decision and public-copy transactions. A worker that loses its lease rolls back its uncommitted decision and does not mark the replacement worker's scan failed. An acknowledgement failure after committed publication preserves that derivative and lets rightful ownership/recovery complete the job. `tests/Integration/leases.php` forces these ownership boundaries; it is separate from the two-process claim test and the SIGKILL recovery suite.

Production audit signing requires `CF_AUDIT_KEY` as a deployment constant/environment variable, generated from at least 32 random bytes and stored outside the DB. The validator accepts 32–4096 bytes and rejects explicit weak/empty values. A production site without it holds service operations with CONFIGURATION.AUDIT_KEY. Only nonproduction with no explicit key uses the WordPress-salt fallback. Back up/manage key rotation separately; signatures are individually verifiable and do not prove missing/deleted events.
